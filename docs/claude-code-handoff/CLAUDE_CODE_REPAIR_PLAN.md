## 2. Phase 1: Security & Path Integrity (P0 Blocker)

### Task 1.1: Fix Windows Drive Letter Stripping Nested Directory Defect (Issue B)
- **Problem:** `let rawPath = item.path.trim().replace(/[*?<>|":]/g, "");` strips the colon from `C:\Users\...`, converting it into relative path `c\Users\...` and creating nested drive directory trees inside the user workspace.
- **Desired Result:** Any absolute Windows path (`C:\...`, `c:/...`) or path repeating the workspace directory name must be cleanly resolved to a path relative to the workspace root, or safely rejected if outside.
- **Affected Files:**
  - `apps/server/src/providers/coding-agents/reasoning/reasoning-coding-adapter.ts:155-184`
- **Recommended Implementation Direction:**
  ```ts
  let rawPath = item.path.trim();
  // Strip Windows drive letter prefix (e.g. C:, c:)
  rawPath = rawPath.replace(/^[a-zA-Z]:[/\\]*/, "");
  // Strip leading slashes and relative parent navigation
  rawPath = rawPath.replace(/^[/\\]+/, "").replace(/^(\.\.[/\\])+/, "");
  // If the path redundantly repeats the workspace folder name at root, strip it
  const wsFolder = path.basename(workspacePath);
  if (rawPath.startsWith(wsFolder + "/") || rawPath.startsWith(wsFolder + "\\")) {
    rawPath = rawPath.slice(wsFolder.length + 1);
  }
  // Sanitize remaining illegal filename characters (excluding slashes)
  rawPath = rawPath.replace(/[*?<>|":]/g, "");
  ```
- **Objective Acceptance Criteria:** Feeding path `"C:\\Users\\test\\myproject\\src\\index.js"` when workspace is `"C:\\Users\\test\\myproject"` writes file strictly to `src/index.js`, NOT `c/Users/...`.

## 3. Phase 2: Multi-Language Project Generalization (P1)

### Task 2.1: Remove Hardcoded Node.js Boilerplate from Generic Reasoning Coder (Issue C)
- **Problem:** `reasoning-coding-adapter.ts:225-295` automatically synthesizes `package.json` with `node --test` whenever tests are requested, even if the user project is Python, Go, or Rust.
- **Desired Result:** Boilerplate synthesis should only occur if the project's profile or specification explicitly targets Node.js. For other languages, let the reasoning model output language-appropriate manifests (`requirements.txt`, `Cargo.toml`, etc.).
- **Affected Files:**
  - `apps/server/src/providers/coding-agents/reasoning/reasoning-coding-adapter.ts:225-295`
  - `packages/shared-types/src/index.ts` (Project profiles)
- **Objective Acceptance Criteria:** A Python project task generates `test_project.py` with `pytest` without generating an extraneous `package.json`.

## 4. Phase 3: Coding Agent Architectural Honesty (P1)

### Task 3.1: Clarify Visible IDE Adapter vs Native Agent Execution (Issue D)
- **Problem:** The UI and reports claim "Visible Antigravity IDE Agent executed task", but the adapter actually runs `ReasoningCodingAgentAdapter` against Ollama or OpenAI directly.
- **Desired Result:**

  2. Implement an actual extension message bridge or CLI invocation if a native Antigravity agent API is provided by the environment.
- **Affected Files:**
  - `apps/server/src/providers/coding-agents/antigravity/visible-ide-adapter.ts:12, 104`
  - `apps/web/src/features/ide/IdeConnectionDeck.tsx`

## 5. Phase 4: Critic & Acceptance Gate Robustness (P1)

### Task 4.1: Separate Test Pass Overrides from Real Code Quality Findings (Issue E)
- **Problem:** Deterministic pass overrides in `critic.ts:88-105` must not silence legitimate Critic quality warnings when tests pass but the code has logic bugs.
- **Desired Result:** If Critic identifies specific quality findings (`quality_findings.length > 0`), the run should enter repair even if exit code was `0`. Only override Critic rejections when the Critic claims tests failed when they actually succeeded.
- **Affected Files:**
  - `apps/server/src/orchestrator/critic.ts:88-105`
  - `apps/server/src/orchestrator/acceptance-gate.ts:40-60`
- **Objective Acceptance Criteria:** An attempt where tests pass (`exitCode 0`) but Critic flagged a severe security vulnerability is rejected for repair.

## 6. Phase 5: Workspace Safety & Snapshot Edge Cases (P2)

### Task 5.1: Enhance SnapshotManager for Deletions and Large Assets
- **Problem:** `SnapshotManager` hashes existing files, but if an agent deletes a user file, rollback must restore the deleted file from the snapshot cache.
- **Desired Result:** Full restoration of deleted files during rollback, and automatic exclusion of large binary assets (`.png`, `.exe`, `.tar.gz`) from in-memory diff generation.
- **Affected Files:**
  - `apps/server/src/git/snapshot-manager.ts:110-160`
- **Objective Acceptance Criteria:** If a task deletes `file.txt`, rolling back the attempt restores `file.txt` with its original contents.

## 7. Phase 6: Frontend State & Telemetry UX (P2)

- **Problem:** If the Fastify server restarts in dev mode, the browser `EventSource` can trigger rapid reconnect loops without updating the local state.
